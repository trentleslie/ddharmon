# feat: Repurpose ddharmon on PyPI — publish the Data Dictionary Harmonization tool as 0.5.0

## Overview

The name `ddharmon` is shared by two unrelated projects. This plan repurposes the
`ddharmon` **PyPI package** (owned by Trent) so it ships the canonical **Data Dictionary
Harmonization** tool as **0.5.0**, published from **`Phenome-Health/ddharmon`** (canonical dev
*and* publisher, so any maintainer there — e.g. Bhargav — can cut releases). Trent owns the PyPI
name and registers that repo as the trusted publisher. `trentleslie/ddharmon` is kept as a content
mirror (for Greptile reviews) and does not publish. It also lands a committed, shared Claude skill
so anyone on the team can cut future releases.

## Problem Frame

- **`trentleslie/ddharmon`** (`origin`): the old *BioMapper2 API client* (Poetry, v0.4.0).
  Migrated and renamed to `biomapper`; now deprecated.
- **`Phenome-Health/ddharmon`** (`phenome`): the real ddharmon — "**D**ata **D**ictionary
  **harmon**ization" (uv/PEP-621, hatchling, requires-python ≥3.12; deps include rapidfuzz,
  ftfy, bertopic, sentence-transformers). Canonical source.
- The two remotes share **no common git history** (`git merge-base --all` is empty), so this
  is not a normal merge — it is a content replacement.
- Trent owns the `ddharmon` **PyPI name** (published 0.1.0 → 0.4.0 as the old client). The team
  wants to repurpose that package for the harmonization tool.

## Requirements Trace

- R1. `ddharmon` 0.5.0 on PyPI is the Data Dictionary Harmonization tool, published from
  `Phenome-Health/ddharmon`.
- R2. `Phenome-Health/ddharmon` is canonical dev + publisher; `trentleslie/ddharmon` is a content
  mirror (Greptile reviews) carrying identical packaging + publish config but not publishing.
- R3. PyPI publishing is automated and tokenless (Trusted Publishing / OIDC) on GitHub Release.
- R4. A committed, shared Claude skill documents the release procedure for colleagues.
- R5. The deprecated BioMapper2-client content is removed from `trentleslie/ddharmon`.

## Scope Boundaries

- Not changing the harmonization tool's source/behavior — only packaging, publishing, repo
  placement, and release tooling.
- Not deleting or rewriting PyPI history for 0.1.0–0.4.0 (immutable; left as-is).
- `[project.urls]` continue to point at `Phenome-Health/ddharmon` (canonical), not the mirror.

### Deferred to Separate Tasks

- Archiving/redirecting any remaining references to the old BioMapper2 client → handled by the
  `biomapper` package separately.

## Key Technical Decisions

- **Publish from canonical (`Phenome-Health`)**: Trent owns the PyPI name but registers
  `Phenome-Health/ddharmon` as the trusted publisher, so maintainers there (e.g. Bhargav) can
  release without depending on Trent. PyPI name ownership is independent of the publishing repo.
  `trentleslie/ddharmon` mirrors the content for Greptile reviews and does not publish.
- **Hatchling + OIDC over Poetry + token**: reuse the already-built tokenless workflow rather than
  the old Poetry packaging; no long-lived secret to manage.
- **Content replacement via a single squash-style commit** on a branch from `origin/main`, so the
  change is a reviewable PR despite the unrelated histories.
- **Skill committed to the canonical branch** so it reaches colleagues and mirrors to trentleslie.

## System-Wide Impact

- **Package identity:** `pip install -U ddharmon` moves users from the 0.4.0 BioMapper2 client to
  the harmonization tool — an intentional breaking identity change (old client → `biomapper`).
  Flagged in the commit (`BREAKING CHANGE`) and CHANGELOG.
- **Two-repo sync:** Phenome-Health is canonical + publisher; trentleslie mirrors content for
  Greptile reviews. The mirror should be refreshed from canonical periodically but is not on the
  release path, so it cannot block or corrupt a publish.
- **Auth surface:** OIDC trusted publishing removes any stored PyPI token from CI.

## Risks & Dependencies

| Risk | Mitigation |
|------|------------|
| Publish job fails because trusted publisher not yet configured | Unit 6 prerequisite is called out; release (Unit 7) gated until it exists |
| Wrong/ broken artifact published irreversibly | Local `build` + `twine check` dry-run passed before any release; release is explicitly gated |
| Canonical/mirror drift over time | Mirror is off the release path (cannot affect a publish); refresh it from canonical periodically. Both carry identical packaging today |
| Users surprised by package identity change | BREAKING CHANGE note + CHANGELOG; old client lives on as `biomapper` |
